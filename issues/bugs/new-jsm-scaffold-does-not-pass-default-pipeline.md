# Bug Report: New JSM Scaffold Does Not Pass Its Default Pipeline

- **Status**: Resolved
- **Date**: 2026-10-13
- **Component**: `profiles/jsm/profile.ps1`, `templates/js/`
- **Impact**: A clean JavaScript repository receives a build entry that does not exist, a test command that rejects an empty initial test suite, and CI that requires a lockfile the scaffold does not create.

## Description

The genericization audit removed project-specific source assumptions but did not supply a neutral initial source file. The portable CI replacement also used `npm ci` unconditionally even though lockfiles must be generated by the consuming repository's selected package manager.

## Resolution

- Scaffold a minimal source entry matching `js.entry`.
- Permit an initially empty Vitest suite.
- Use `npm ci` when a lockfile exists and `npm install` for the first clean pipeline.
- Keep unminified Vite outputs unminified by applying Terser only to `.min.js` outputs.
- Recalculate a no-remote project path after package/module identity discovery.

## Verification

Initialization regressions assert the source entry and package-derived project path. JavaScript syntax, JSON parsing, and the complete Pester suite pass.
